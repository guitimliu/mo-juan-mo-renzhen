# 新北市法制局「訴願決定書查詢系統」抓取評估（2026-09-13，尚未實作）

目標：https://web.law.ntpc.gov.tw/Su_search01.aspx ，把歷年訴願決定書全文抓回，擴充 KB `ZOMMOWFOT2`（目前僅 101 件）。

## 網站機制（實測）
- 查詢表單是 ASP.NET WebForms，但按查詢後 302 到**純 GET** 網址，之後完全不需要 ViewState／CSRF：
  - 列表：`/Scripts/Su_list02.aspx?sdate=YYYYMMDD&edate=YYYYMMDD&page=N`（西元日期；每頁 20 筆；頁面有「查詢結果共計：N筆」與「頁次：a/b」）
  - 明細：`/Scripts/Su_contents03.aspx?NO=3&ecode=Z00000&ecase=新北府訴決&eno=<發文字號>&startdate=&enddate=&EANO=<案號>&EDATE=<日期>`（列表頁的 href 直接可用）
  - 另有列印版 `/Scripts/PrintSu_contents03.aspx?...`（同參數，版面更乾淨，可作為解析來源）
- 明細頁**全文是 HTML 內文**（非 PDF），欄位：案號、要旨、發文日期、發文字號、相關法條（`tr#cph_content_trRelaLaw`，並附法條連結）、全文。全文用 `<br>` 分行，主文／理由／委員名單／教示／日期都在同一段。
- 無 robots.txt（404）。回應約 0.15–0.2 s/請求。單次查詢日期範圍不限（2004–2026 一次查得 26,676 筆／1,334 頁）。

## 抓取設計建議
1. **兩階段**：(a) 逐年逐頁抓列表 → `index.jsonl`（案號、日期、標題、明細 URL）；(b) 依 index 抓明細，原始 HTML 落地 `raw/<年>/<案號>.html`，可中斷續跑（以案號判斷已抓）。
2. 單執行緒 + 固定間隔（0.5–1 s）+ 重試（指數退避），UA 標明用途。不要開多執行緒打政府站。
3. 解析成 `decisions.jsonl`：`{案號, 發文字號, 發文日期(ISO), 要旨, 案件類型(由要旨「因…事件」切出), 相關法條[], 原處分機關, 訴願人(已遮罩), 主文, 理由, 裁決類別(駁回／撤銷／不受理，由主文判定), 委員[], 全文}`。
4. 匯入 KB：沿用 `backend/tools/build_kb_corpus.py` 的 sidecar 格式（`category=decision`、`year`、`case_type`、`outcome`、`doc_no`），每篇一個 `.txt`；或改成 `doc_no=案號`。26k 篇對 Titan Embed v2 + S3 Vectors 的 ingestion 成本很低，但 KB 大小會讓「相似案」檢索更需要 metadata 過濾（`case_type`／`year`）。
5. 增量更新：之後只抓 `sdate=上次最大日期` 之後即可。

## 風險與注意
- **著作權**：頁尾寫「未經允許，不得以任何形式複製」，但訴願決定書屬公文書，依著作權法第 9 條第 1 項第 1 款不得為著作權標的；仍建議禮貌抓取，且黑客松成果若公開，註明來源。若要正式使用，可向法制局申請資料或確認是否已在 data.ntpc.gov.tw 開放（本次快速查沒找到現成資料集，未完全確認）。
- **個資**：訴願人姓名已由網站部分遮罩（陳○頡），但代理人律師姓名、原處分機關、案件編號、委員姓名完整。既有 PII 前處理（取代法）可套用；入 KB 前至少不要再增加還原可能。
- **穩定性**：明細頁全文分段靠版面（全形空白 + `<br>`），不同年代格式可能不同（早期可能無「相關法條」列）。先抓 raw HTML 再解析，解析器可反覆迭代。
- **重複／勘誤**：同一案可能有更正決定書；以案號 + 發文字號為主鍵。
- **KB 費用／品質**：目前 KB 101 篇即可命中正本；擴到 26k 篇後要重測 113-16 的 top-k 是否仍正確，並排除本案自身（`doc_no` 過濾）。

## 建議順序
1. 先抓 2020–2026（約 9.3k 篇，~2 小時）驗證解析與 KB 效果，再回補 2004–2019。
