# 前端與 D 的串接待辦

已接收的契約原件位於 `data/poc/03_介面規格.md`，保留原檔內容。

## 已定義

- `POST /cases`：multipart 欄位 `petition_image`、`disposition_image`，回傳 `{ "case_id": "poc-001" }`。
- `GET /cases/{case_id}`：輪詢案件最新結果。
- S1 OCR、S2 案件摘要、S2.5 程序、S3 檢索、S4 草稿、S5 檢核的各階段內容欄位。

## 尚未定義，不視為已凍結的契約

- GET 最外層 envelope：階段結果存在哪個 key，以及未完成時為 null、缺省或其他值。
- 目前階段與生命週期：等待、處理中、完成、失敗的欄位及 enum。
- 失敗原因、重試條件、輪詢間隔、逾時與取消能力。
- S4 citations 只有全域引用，尚無段落索引；每段引用映射需後端補充契約。
- S5 的規格摘要與 `07_檢核.py` 輸出的 `checks`／`score` 不同，需選擇完整回傳形狀。

`src/data/pipeline.json` 的 s1、s2、procedure、s3、s4、s5 外層 key 是前端 fixture 容器，不代表已確認的 GET response。現在的 12 秒流程是本機模擬；「停止模擬」只會停止本機計時器，沒有宣稱能取消後端工作。
