# POC 介面規格（各階段之間的 JSON 契約）

所有階段以 JSON 交換，任何人可以用假資料先跑自己那段。**先凍結這份，再各自開工。**

## S0 前端 → 協調器
POST /cases　multipart：petition_image（訴願書）、disposition_image（處分書）
回傳：{ "case_id": "poc-001" }
GET /cases/{case_id}　回傳下列所有階段的最新狀態（前端輪詢即可，不需 websocket）

## 附錄 A：GET /cases/{case_id} 最外層格式（2026-09-12 補定，回應 f2e/docs/backend-integration.md）
{
  "case_id": "poc-001",
  "status": "queued | running | done | error",
  "current_stage": "S3",                       // 進行中的階段；done 時為 null
  "adapter_mode": "stub | bedrock",
  "created_at": "2026-09-12T14:03:00+08:00",
  "updated_at": "…",
  "stages": {
    "S1":   {"status": "done",    "data": {…S1…},   "error": null, "elapsed_ms": 1200},
    "S2":   {"status": "done",    "data": {…S2…},   "error": null, "elapsed_ms": 800},
    "S2_5": {"status": "done",    "data": {…S2.5…}, "error": null, "elapsed_ms": 5},
    "S3":   {"status": "running", "data": null,     "error": null, "elapsed_ms": null},
    "S4":   {"status": "pending", "data": null,     "error": null, "elapsed_ms": null},
    "S5":   {"status": "pending", "data": null,     "error": null, "elapsed_ms": null}
  },
  "error": null                                 // 整體失敗原因；某階段失敗則該階段 status="error" 並停在那裡
}
- 階段 status enum：pending / running / done / error / skipped。
- 前端輪詢間隔 1500 ms；status ∈ {done, error} 即停。逾時由前端自定（建議 120 s）。
- 暫不提供取消端點；「停止」只停前端計時器。

## 附錄 B：S4 citations 段落映射（補定）
citations 每筆加 section 與 index：
  {"text": "洗錢防制法第22條第1項", "source": "statutes[0]", "section": "reasons", "index": 0}
- section ∈ {facts, reasons, instruction}；index 為 reasons 陣列索引，facts／instruction 為 0。
- 前端依 (section, index) 把引用掛到對應段落。

## 附錄 C：S5 回傳形狀（補定）
S5 直接回傳 07_檢核.py 的完整輸出 {checks:[{group,item,pass,note}], score:{…}}，
另加 summary 欄位 = 本規格原本的 S5 摘要（sections_present, citation_grounded, citation_total,
gold_citations_recalled, gold_citations_missed, holding_match），由後端從 checks 算出。
